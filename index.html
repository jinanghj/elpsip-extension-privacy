ELPSIP 출원서 작성 — 개인정보처리방침

시행일 2026년 11월 18일 · English

이 방침은 Chrome 확장프로그램 ELPSIP 출원서 작성 1.0.5가 처리하는 정보를 설명합니다. ELPSIP 직원의 국내 특허·디자인·상표 서식 PDF·BIB 작성, 국내·해외 사건 완료 안내 Gmail 초안 작성, DB 비용관리 금액을 이용한 견적서·청구서 PDF 작성을 지원합니다.

1. 처리하는 정보

서식 작성 시 사건관리 시스템(db.elpsip.com)의 사건·출원인 정보, 명칭, 출원번호·일자, 특허고객번호, 포괄위임번호, 상품·물품류, 상표견본과 사용자가 입력한 서식 항목을 읽습니다.

메일 기능은 직원이 DB에서 국내·해외 사건의 출원일·등록일자·중간사건(1·2차 OA) 제출일을 저장할 때 그 저장을 감지합니다. 직원이 초안 작성을 누르면 사건·중간사건 정보, 고객명·고객 담당자, 안내메일 수신자·참조자 이메일, 출원·등록·제출 일자, 해외 사건의 국가·등록번호·국제출원번호·지정국 진입기한 등 메일 템플릿에 필요한 DB 항목과 상표 사건의 상표견본 그림을 읽습니다. 직원 본인의 이름·직급·공통 서명, DB 로그인 이메일과 Google 계정 이메일, Gmail 설정의 서명을 사용합니다. 첨부파일이나 PC의 폴더·파일은 읽지 않습니다.

견적서·청구서 기능은 직원이 DB 비용관리 화면에서 [견적서 작성]·[청구서 작성]을 누르거나 작성 창에서 관리번호로 [DB 불러오기]를 누를 때만, 해당 사건과 직원이 고른 같은 묶음 사건의 정보(관리번호, 고객명·출원인, 상표명·명칭, 상품류, 출원번호·출원일·등록번호, 상표견본 그림)와 비용관리 표의 업무명칭·세부업무·견적총액·청구금액을 읽습니다.

Google 계정 확인, 서명 조회 및 초안 생성용 OAuth 접근 토큰은 Chrome 인증 API로 받아 작업 중 사용합니다. 쿠키·비밀번호를 읽거나 저장하지 않습니다. 방문 기록, 위치, 관련 없는 웹사이트 내용은 수집하지 않습니다.

2. 이용 목적과 전송

  • 서식 파일 작성은 사용자 PC에서 처리하고 사용자가 고른 폴더에 저장합니다. Windows 저장 도우미는 외부 통신을 하지 않습니다.
  • 견적서·청구서 PDF는 작성 창(사용자 PC)에서 만들고, Chrome의 저장 창에서 직원이 고른 위치에 저장합니다. 견적서·청구서 정보는 외부로 전송하지 않습니다. 다운로드 권한은 이 PDF 저장과 그 저장 결과 확인에만 사용하며 다른 다운로드 기록은 읽지 않습니다.
  • DB 조회는 사용자의 기존 로그인 상태로 같은 사이트에서 GET 요청만 사용합니다. DB 값을 변경하지 않습니다.
  • 직원이 확인 창에서 초안 작성을 누르면 수신자·참조자·제목·본문(상표 사건은 본문에 넣는 상표견본 그림 포함)을 Google Gmail API에 전송하여 본인의 임시보관함에 초안을 만듭니다. 첨부파일은 전송하지 않으며 직원이 Gmail에서 직접 추가합니다.
  • 본문 끝에 넣을 서명을 확인하기 위해 Gmail 설정의 서명을 읽기만 합니다. Gmail 설정은 변경하지 않습니다.
  • 자동 메일 발송이나 기존 Gmail 초안을 덮어쓰는 기능은 없습니다. Google의 gmail.compose 권한에는 발송 권한도 포함되지만 이 프로그램은 초안 생성 API만 호출합니다.
  • 개발자 서버, AI/LLM, 광고·분석 서비스에 정보를 전송하지 않습니다. 데이터를 판매하거나 업무와 관계없는 목적으로 이용하지 않습니다.

3. 보관과 삭제

서식 작성창과 견적서·청구서 작성 창의 정보는 창을 닫으면 메모리에서 사라집니다. 견적서·청구서 작성 창에 넘길 DB 값(사건 정보·금액·상표견본 그림)과 작성 창을 연 DB 탭 번호는 브라우저 세션 저장소에 두며 브라우저를 닫으면 삭제됩니다. 저장한 PDF·BIB·JPG는 사용자가 관리합니다.

직원 이름·직급·공통 서명 설정과, 같은 업무의 중복 초안을 막기 위한 사건·업무 식별자, 완료일, 직원 이메일, 생성 상태와 초안 ID를 해당 Chrome 프로필의 로컬 저장소에 보관합니다. 저장 직후 확인 창을 띄우기 위한 대기 정보는 브라우저 세션 저장소에 최대 3분간만 두며 탭을 닫으면 삭제합니다. 메일 본문에 쓴 DB 값, 상표견본 그림, Gmail 서명과 OAuth 토큰은 확장의 저장소에 보관하지 않습니다. 인증 캐시는 Chrome이 관리합니다.

확장프로그램을 삭제하면 확장 로컬 설정과 기록이 제거됩니다. 이때 중복 방지 기록도 사라집니다. Gmail 초안·메일과 로컬 생성 파일은 자동 삭제하지 않으며 사용자가 해당 서비스·폴더에서 직접 관리합니다. Google 계정의 연결된 앱 설정에서 접근 권한을 해제할 수 있습니다.

4. 권한과 실행 범위

서식 작성은 activeTab·scripting·nativeMessaging을 사용합니다. 메일 기능은 storage·identity와 db.elpsip.com·www.googleapis.com·gmail.googleapis.com 사이트 권한을 사용합니다. 견적서·청구서 기능은 db.elpsip.com 사이트 권한, storage(세션 저장소), scripting, downloads를 사용합니다.

db.elpsip.com 페이지에서 자동으로 실행되는 스크립트(콘텐츠 스크립트)는 두 가지 일만 합니다. (1) 위 세 날짜 칸의 저장을 감지하며, 값이 실제로 바뀌어 저장된 것을 GET으로 다시 확인한 경우에만 메일 확인 창을 띄웁니다. (2) 사건 비용관리 화면에 [견적서 작성]·[청구서 작성] 버튼을 추가하고, 직원이 버튼을 누를 때만 사건·비용관리 정보를 GET으로 읽습니다. 작성 창의 [DB 불러오기]는 열려 있는 db.elpsip.com 탭에서 확장 패키지에 들어 있는 읽기 스크립트를 실행해 해당 관리번호 사건을 GET으로 읽습니다. 확장이 설치된 직원 프로필에서 한 작업만 처리하며, 다른 기기·프로필·브라우저가 닫힌 동안의 변경은 감지하지 않습니다.

5. Google 사용자 데이터

Google API에서 받은 정보는 위 메일 초안 기능에만 사용합니다. 견적서·청구서 기능은 Google API를 사용하지 않습니다. 제한적 사용(Limited Use)을 포함한 Google API Services User Data Policy 및 Chrome 웹스토어 사용자 데이터 정책에 따라 처리합니다. 접근 범위는 초안 생성용 gmail.compose, 서명 읽기용 gmail.settings.basic, 계정 확인용 userinfo.email입니다.

Privacy Policy — ELPSIP Application Writer

Effective November 18, 2026 · Version 1.0.5

Data and purpose

This internal staff extension generates Korean patent, design and trademark filing documents, completion email drafts for domestic and overseas cases, and quotation/invoice PDFs from the amounts in the DB cost-management page. When an employee saves a filing date, registration date or 1st/2nd office-action response date in db.elpsip.com, it detects that save. If the employee then chooses to create a draft, it reads the case, customer, contact, recipient/CC and date fields needed for the template (for overseas cases also the country, registration number, international application number and national-phase deadline), plus the trademark specimen image for trademark cases. It also uses the employee's name, title and fallback signature, the DB login email, the Google account email and the Gmail signature. It does not read attachments or local folders for email.

Only when an employee clicks "Create quotation" / "Create invoice" on a case cost-management page, or "Load from DB" with a docket number in the quotation window, the extension reads that case and any same-family cases the employee selects (docket number, customer/applicant name, mark or title, classes, application/registration numbers and dates, trademark specimen image) and the work name, work detail, quoted amount and billed amount in the cost table.

Processing and sharing

Filing PDF/BIB/JPG files are generated locally. The Windows helper has no network access. Quotation/invoice PDFs are rendered locally in the extension window and saved to a location the employee chooses in Chrome's save dialog; quotation/invoice data is not transmitted anywhere. The downloads permission is used only to save that PDF and check the result of that save; other download history is not read. DB data is fetched using same-origin GET requests and the existing login session, without writing to the DB. When staff confirm draft creation, the recipients, CC, subject and body (including an inline trademark specimen image where applicable) are sent to Google Gmail API to create a draft in the employee's mailbox. No attachments are sent; staff add them in Gmail. The Gmail signature is read only, and Gmail settings are not changed. The extension has no email sending or existing-draft overwrite operation. Google's gmail.compose scope also permits sending, but the product only calls draft creation.

No data is sent to developer servers, AI/LLM, advertising or analytics services, or sold or used for unrelated purposes. The extension does not read passwords, cookies, browsing history, location or unrelated websites. OAuth access tokens obtained through Chrome Identity are used transiently for account verification, signature lookup and draft creation.

Retention and control

Data in the filing popup and the quotation window is discarded when the window closes. The DB values passed to the quotation window (case details, amounts, specimen image) and the originating DB tab ID are kept in browser session storage and removed when the browser closes; generated files remain under the user's control. The employee's name, title and fallback signature, and duplicate-prevention records (case/work identifiers, date, staff email, status and draft ID) are stored locally in the Chrome profile. A pending-save marker used to show the confirmation dialog is kept in browser session storage for at most three minutes and removed when the tab closes. DB values used in the email body, specimen images, Gmail signatures and OAuth tokens are not stored by the extension. Chrome manages the authentication cache.

Uninstalling the extension removes its settings and local history, including duplicate-prevention history. It does not delete Gmail drafts or generated files. Users manage those in Gmail or their local folders and may revoke Google account access in their connected-app settings.

Permissions and Google API data

The extension uses activeTab, scripting and nativeMessaging for filing documents; storage, identity and host access to db.elpsip.com, www.googleapis.com and gmail.googleapis.com for email drafts; and host access to db.elpsip.com, storage (session), scripting and downloads for quotations/invoices. Content scripts that run automatically on db.elpsip.com do only two things: (1) watch saves of the three date fields above and show the email dialog only after a GET request confirms the changed value was saved; (2) add "Create quotation" / "Create invoice" buttons to the case cost-management page and read case and cost data with GET requests only when the employee clicks them. "Load from DB" in the quotation window runs a read-only script packaged in the extension in an open db.elpsip.com tab to fetch that docket's case with GET requests. Only actions in a Chrome profile with the extension installed are handled; other devices, profiles and changes while the browser is closed are not monitored.

Google data is used only for the draft feature; the quotation/invoice feature does not use Google APIs. Its use adheres to the Google API Services User Data Policy, including Limited Use, and the Chrome Web Store User Data Policy. Scopes are gmail.compose (draft creation), gmail.settings.basic (reading the signature) and userinfo.email (account verification).
